# Управление ресурсами в Gonflict

Этот документ описывает правила работы с ассетами и сервисами загрузки в проекте. Документ дополняет общие требования Clean Architecture и служит справочником при добавлении новых ресурсов.

## Базовые принципы

- Любая работа с ассетами (карты, звуки, скрипты, тайлы, шрифты) проходит через интерфейсы из `internal/interfaces/repositories.go`.
- Доменные и application-слои не знают о файловой системе: данные поставляются через репозитории.
- Репозитории реализуются на уровне инфраструктуры (`internal/repositories/*`) и внедряются через DI в адаптеры/use cases.
- Новые типы ресурсов оформляются по тому же шаблону: интерфейс → реализация → тесты → регистрация в `App`.

## Классификация репозиториев

| Категория | Интерфейсы | Реализация | Содержимое |
| --- | --- | --- | --- |
| Сырые файлы | `IFileRepository` | `internal/repositories/raw` | Низкоуровневое чтение данных из `assets/` |
| Обработанные данные | `IMapsDataRepository`, `ITilesetRepository`, `IScriptsRepository`, `IFontsRepository` | `internal/repositories/processed` | Конвертация сырого файла в структуру домена |
| Игровое состояние | `IGameRepository`, `ITanksRepository`, `IBulletsRepository`, `IAnimationsRepository` и др. | `internal/repositories/game` | In-memory объекты, обновляемые в ходе игры |

## Рабочий процесс при добавлении ассета

1. **Добавьте файл** в соответствующую директорию `assets/` (например, карту уровня в `assets/levels/36.bcmap`).
2. **Расширьте интерфейс**, если требуются новые методы доступа. Интерфейсы лежат в `internal/interfaces/`.
3. **Обновите репозиторий**: добавьте код чтения/парсинга в слой infrastructure.
4. **Напишите тесты** в `internal/repositories/<category>/*_test.go`, которые проверяют загрузку и преобразование данных.
5. **Зарегистрируйте зависимости** в `internal/app.go`: новый репозиторий должен попадать в use cases/adapters через конструктор `New*`.
6. **Обновите документацию** и убедитесь, что README отражает новые ресурсы.

## Карты уровней

- Формат `.bcmap` описывает сетку 26×26.
- Загрузка выполняется через `IMapsDataRepository`, который использует `IFileRepository` для чтения YAML/бинарных данных.
- Работа с картой в use cases (`MapUseCases`) ограничивается доменными структурами, без прямого обращения к файлам.

## Тайлы и спрайты

- Конфигурация тайлсетов хранится в `assets/tiles/*.yml`.
- `ITilesetRepository` возвращает предобработанные структуры с координатами спрайтов и анимаций.
- `TileService` и `AnimationService` отвечают за интерпретацию конфигурации и обновление кадров.

## Скрипты AI

- Lua-скрипты лежат в `assets/scripts/` и загружаются через `IScriptsRepository`.
- Адаптер AI (`internal/adapters/game/input_adapters/ai`) получает ссылку на `ILuaEngine` и `IAIUseCases`; прямое чтение файлов внутри use case запрещено.

## Шрифты и текст

- Шрифты находятся в `assets/fonts/` и доступны через `IFontsRepository`.
- Всё отображение текста в Presentation слое использует готовые шрифты; хранить `[]byte` шрифта в состоянии игры не требуется.

## Проверки и тестирование

- После изменений запустите `just fmt`, `just lint` и `just test`.
- Для репозиториев предпочтительно писать unit-тесты, работающие с временной файловой системой или фикстурами.
- При добавлении крупных ассетов обновите `.gitignore`/`_assets` при необходимости.

## Советы

- Не дублируйте путь до ассета в нескольких местах. Используйте константы/конфигурацию на уровне репозитория.
- Помните про ограничение на размер бинарников в репозитории; храните только необходимые файлы.
- Избегайте глобальных синглтонов: используйте конструкторы `New*` и внедрение зависимостей в `App`.

Следуя этим правилам, можно безопасно расширять набор ресурсов, не нарушая чистоту архитектуры.
